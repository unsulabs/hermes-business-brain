# ce-evaluar-recurso

1. Define which concrete business need is being solved. Search first whether native Obsidian (Bases, Properties, Templates, CLI) or the current engine already does it.
2. Inspect the original source: URL/release/commit/versions, maintainability, APIs, dependencies, license of code/templates/media, and security. Do not infer compatibility from a video.
3. For `obsmd-projects/obsidian-projects`: archived on GitHub and discontinued in 2025; **do not install** nor copy code without license analysis. Consider only the views/templates pattern.
4. Compare need, existing function, risk, cost, no-plugin alternative, reversibility, visual proof and migration cases.
5. Prepare a research sheet with source evidence and a synthetic experiment; do not copy code nor treat the technology as approved.
6. Request a human decision to add the dependency; test in an isolated installation and uninstall without knowledge loss.
**Output:** adopt/adapt/reject/pending with missing evidence and license.
