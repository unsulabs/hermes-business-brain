# ce-consulta

If the message brings new conversational material to preserve/analyze, enter first through [ce-banco-transcripciones](../ce-banco-transcripciones/SKILL.md). Retrieve across all eligible types: research, sources, autonomous notes, D/X, corpus and authorized external references. Metadata -> candidates -> passages with neighbors; broaden to the original if meaning changes. Without purpose-based permission don't retrieve content. Don't load the whole corpus by default. Use [ce-revisar-antecedentes](../ce-revisar-antecedentes/SKILL.md) when historical criteria matter or a search fails; literal/FTS search orients candidates, it doesn't understand nor prove absence. A corpus result requires version/hash/spans and real reading of the original; don't claim pending CLI capabilities.

1. Identify **the task the person wants to perform**, business, matter, entity, date and permissions. If an existing vault exists, resolve it (brain_resolve_vault, per the [obsidian-router skill](../obsidian-router/SKILL.md)) and verify its path, native registry and instructions **before any `rg`, `ls`, `cat`, CLI or other read inside that vault**; the path in the prompt does not replace that check. Then recover its state and current notes; don't return to onboarding. If **any** brain_* tool fails because of a dependency of the Python interpreter in use -- including brain_query, brain_status and brain_validate_vault -- first check `command -v python3.11 python3.12 python3.13` and the venv already available; on a Mac with Homebrew also check `/opt/homebrew/bin/python3.11`. Run `python -c "import yaml, jsonschema"` with the candidate and retry the same operation. A `python3` failure does not authorize declaring the query impossible nor asking for an install if another existing interpreter works. Record the interpreter you actually used; don't claim another failed if you didn't test it in this session. Don't assume the question asks for an audit report: it may ask for a proposal, a decision, an instruction or an action.
2. Search the D/X syntheses and the pertinent autonomous units (offer, service, process, project, decision). Use Bases, map and relations as navigation routes. For a natural request use `brain_query --orientar --texto ...`: it orders fragments by word overlap and shows state, currency and sources. To verify an exact phrase, use `brain_query --texto ...` without that option. The `buscar` subcommand can broaden terms, and `autoridad --tema ... --ambito ... --fecha ...` queries explicit authority if it exists (CLI subcommands, not exposed as v2 plugin tools). An empty result doesn't prove absence of knowledge: try human names, synonyms and reading the map. None of these searches understands intent nor attests that the source proves the fragment.
3. Open the candidate notes and the pertinent admissible original; the record card (`ficha`) F locates an original, but doesn't substitute for it. `lectura: leida_completa` in a card documents an earlier reading, not a reading **in this session**. If you only opened the card, cite the card and say you didn't check the original now; don't cite the README, contract, transcript or original repository as if you had read them. Before answering, contrast each citation to an original with a reading operation actually executed and with the passage that supports the claim. Separate claim owner from context and date of the experience, editorial version, coverage for this task and currency. Authorized primary histories can support background, with explicit date and currency; rejected editorial texts are never authority nor draft for reconstructing the answer. Don't attribute a client project to the business just by technical similarity.
4. Build the **requested output** with that business's concrete mechanisms, language, decisions and exceptions. For another person or agent, include what to observe, what to do, who decides and when to stop. Use the owner's declared criterion for strategy and method; use contract, registry and accounting when the claim is an obligation, sale or payment. Don't turn price history into a current rate. **Without an admissible financial record, express "billing/payment not substantiated" or "data unavailable"; don't record zero nor infer it didn't happen.** A zero requires a complete record for the consulted period and scope that supports it.
   If the request is open-ended about the business, recover the direction, portfolio and pertinent units before synthesizing. Check whether the owner declared purpose, current method, the different ways of working, product development or future research as central. A short answer may choose examples, but must keep the distinctions needed for that audience and task: current activity, product in development and future possibility are not equivalent. Explain the general mechanism first. A well-documented case or product can illustrate it when it clarifies the raised need; don't introduce a product foreign to that need just to discard it. If developing several solutions is part of the identity, explain the logic without turning one particular offering into the whole business. Propose the next work from the person's expressed need and the pending cross-cutting decisions; if there is no concrete opportunity, use a short exercise that serves more than one mode.
5. Check the output against the source and a pertinent countercheck: which claim would change if it were another business or a historical version? In a conversation follow-up, also verify **who said or committed to what and with what degree of certainty**: intention to recommend is not a conversation already held, an offered session is not an accepted appointment and interest is not hiring. Compare each actionable sentence of the draft with the original passage and fix any jump before delivering. If it's interchangeable, missing a material mechanism, or makes the business speak as an external observer, go back to the source and redo the piece. If a datum that changes a decision is missing, delimit that point without emptying the whole answer.
6. Deliver the main work first. Add locators and material limits in a brief CONTROL; don't move CONTROL language into client-directed text. If the task requires editing, follow [ce-cambios](../ce-cambios/SKILL.md) and propagate impacts. Keep the raw output and the owner's correction to improve notes and system rules.
**Output:** specific usable work; sources and currency checked; uncertainty only where it alters use; correction incorporated into the knowledge when authorized.
