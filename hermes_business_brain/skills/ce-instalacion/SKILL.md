# ce-instalacion

**0. Branch before installing:** identify whether the user already has a vault; before reading its content resolve `obsidian-router` and its instructions ([obsidian-router skill](../obsidian-router/SKILL.md)). Then check `90_Sistema/config_empresa.yaml` and D/X or sources. If it exists, **do not create another one nor reinstall**: activate the guide `guia/ACEPTACION_REAL_CODEX_INSTANCIA_EXISTENTE.md`, check the checkout without destroying changes and run `aceptacion_integracion_local.py` in read-only mode. Updating code does not modify the instance; migrations require additional authorization.

1. Read `guia/PRIMERA_EMPRESA_CON_CODEX.md`, C0–C2; verify the repo root and don't confuse `master` with an instance.
2. READ-ONLY diagnostics: `brain_doctor` and Obsidian version verified via GUI/CLI if available; don't trust a path as proof of function.
3. Communicate real requirements and blockers. The expressed request to install and build the business authorizes the necessary operations within the chosen location; don't repeat permissions already granted. Ask before publishing data, sending messages, installing external plugins or using another account. Don't install `obsidian-projects` (archived) or TaskNotes automatically. Native Bases and Templates first.
4. Install Python dependencies into a venv if the commission already authorizes it, and check the plugin with `hermes plugins doctor hermes-business-brain --ci` (or run the plugin repo tests via its `.venv`: `python -m pytest tests/ -q`). If there is no internet, don't invent an installation.
5. Obtain the name and private destination only if they are not in the context and no instance exists; generate a stable ID. `brain_create_vault` fails if the destination exists. Never copy `ejemplos` nor data from another instance into a real business.
6. For the newly created instance, check `brain_validate_vault` and open it as an existing vault in Obsidian if the GUI is accessible. **Finish registration and resolution with the router before moving to discovery**: after opening the folder in Obsidian, run `brain_register_vault --vault PATH --nombre "Name" --alias BUSINESS_ID`, followed by `brain_resolve_vault --selector PATH`, per the [obsidian-router skill](../obsidian-router/SKILL.md). The tool only writes the local agent registry, with a backup; it never alters the native registry nor the vault. After resolving, observe `Inicio.md` and some `.base` view. If the GUI or the router are not available or don't confirm the path, mark that integration `NO VERIFICADO`, keep the instance and explain the concrete blocker; continue only independently authorized work outside the vault. Don't ask the owner to edit JSON.
7. Report six surfaces separately: code, Python, Obsidian GUI, Bases, private instance, sources/connectors. Mark `NO VERIFICADO` where appropriate. Continue with `ce-descubrimiento` and `ce-arquitectura-conocimiento` when several matters exist. Don't close the commission by installing: produce usable knowledge and prove a task with `ce-consulta`.

To receive transcripts, prepare the persistent private configuration and check the dependencies of the [default cycle](../ce-banco-transcripciones/references/flujo-predeterminado.md#instance-and-dependency-preparation). Vault routing comes included (brain_register_vault / brain_resolve_vault); read the [obsidian-router skill](../obsidian-router/SKILL.md) without installing a global skill. If it is missing, keep the authorized progress outside the vault and leave its access/integration pending resolution; registering a vault does not replace the resolver. Don't import authorizations nor pilot profiles into a new instance.

**Forbidden:** installing external plugins without consent; changing Obsidian's security mode without explaining; uploading business data to Git without express authorization; declaring the brain complete for having passed unit tests.
